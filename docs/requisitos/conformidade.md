# Requisitos e limites da primeira execução

| Disciplina | Relação com esta execução | Pendências |
|---|---|---|
| Application Development | Web HTML/CSS/JS; Express GET/POST, validação, MongoDB, listagem, total/distribuição por cultura, erros/404, README | Pitch de 2–3 min, revisão final da rubrica e publicação/entrega. Não declarar entrega acadêmica encerrada; não afirmar que a execução foi medida em quatro horas. |
| Cross-Platform | API e contratos disponíveis, pasta Flutter reservada | Aplicativo inteiro: >=5 telas, >=3 dashboards territoriais, gráficos/históricos/tendências, alertas explicados, estado local/global, API, offline, formulário, acessibilidade, benefício social, README/repositório público/vídeo <=3min |
| Data Science | Fronteira regional/local documentada | Dados reais RMSP, tratamento/EDA, dois modelos avaliados, notebook/relatório e síntese executiva |
| POO Java | Fronteira independente e escopo documentados | Implementação, persistência, console, padrões e >=5 testes JUnit com Mockito |
| Software Engineering | Arquitetura, backlog relacionado, critérios e evidências desta etapa | Quadro real, responsáveis/horas, registros Scrum, acesso verificável, capturas e PDF. Nenhuma edição Trello feita |
| Aprendizado Profundo | Atividade independente | MLP roubo/furto SP em controle acadêmico separado |
| Sistemas Operacionais/Redes | Atividade independente | Documento oficial Windows Server/SMB/NTFS/RAID, sem VM |
| Edge Computing | Presencial, sem integração presumida | Aguardar escopo do professor |

As datas das disciplinas, exceto Flutter, precisam de confirmação. Este repositório não prova validação com usuários reais, entregas finais, impacto social ou implementação dos módulos reservados.
